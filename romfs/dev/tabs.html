Tabs test — diagnostic ladder

Four progressive variations that isolate each layer of the tab-switching mechanism. Start at A and work down — the first one that behaves wrong points at the broken layer.

Variation A — visible radios, no CSS tab switching

Three pill-styled labels, each wrapping a visible radio button + its caption. Tap a label — the selected radio's dot should fill in, the previously-selected one should empty. We're only checking radio tap routing + the radio painter's visible square here; no panels switch.

Variation B — `~` sibling combinator, hidden radios

Tabs and panels driven by input:checked ~ .panel. Tap any tab — the active tab should highlight in yellow AND the panel text below should change.

Panel one — fish, dolphins, whales.
Panel two — eagles, hawks, sparrows.
Panel three — lions, tigers, jaguars.

Variation C — `+` adjacent sibling combinator

Each panel is the IMMEDIATE next sibling of its radio (using +) — panel switching tests the + matcher. The active-tab label is expected NOT to highlight here because the labels appear in the DOM BEFORE the radios, and CSS ~ only finds PRIOR siblings — so no :checked radio can ever be a prior sibling of the labels. This is a CSS-spec limitation, not an engine bug. Place radios before tabs (Variation B / D) to get a working label highlight.

Cats: meow, purr, nap, nap.
Dogs: bark, fetch, sleep.
Birds: chirp, fly, sing.

Variation D — apps.html-shaped inline-flex pill tabs

Variation B with display: inline-flex + min-width + border-radius: 999px pill labels. This matches the failing apps.html geometry. If only D is broken, the inline-flex hit box is the bug.

Featured: alpha, beta, gamma.
Community: delta, epsilon, zeta.
Experimental: eta, theta, iota.
