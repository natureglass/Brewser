<iframe> — Tier 1B inline preview

Each iframe below fetches its src, parses the response HTML, and grafts the body as the iframe's subtree. Scripts inside the iframe are skipped. Internal <style> blocks are selector-scoped so they only match descendants of their iframe — embedded CSS won't leak into this parent page's cascade.

1. Same-origin local fixture

Loads another brewser:// fixture inside an iframe. Most reliable: no network, no CSS-scoping conflicts.

2. Custom size

No width / height attrs — falls back to the HTML spec defaults (300×150) so you can see the frame without any sizing hints.

3. Inline next to text

Iframes are replaced-inline (like <img>), so they can sit alongside text on the same line. Here's some lead-in text, then an iframe: and the line continues after it (or wraps, depending on width).

4. External https page

Fetches a real external page over HTTPS. Caveat: many real pages depend on scripts or external CSS we don't run inside the iframe — content will look stripped-down. The page below is small and mostly markup.

Known Tier 1B limitations: sandbox / allow / CSP attributes are parsed but not enforced. Cross-origin is not isolated. Iframe scripts never run. CSS selectors targeting html / body inside the iframe won't match (the iframe has no inner body element). Tier 1C (separate JS context + sandbox enforcement) is a future task if a use case needs it.
